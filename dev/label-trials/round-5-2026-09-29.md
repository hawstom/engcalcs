## Part 1: Protocol (pre-registered)

### 1.1 Question

Does what we have learned about the placers on the public bench (EPA Net1, Net2, Net3, and Net3 on
the world map at Novato) hold on networks nobody tuned against: larger, denser, differently shaped
networks that run off the screen on every side? Where does each placer fail, and does Net3 hide
it? And which of Tom's rules (`dev/label-placement-rules.md`, Part A) does the evidence support,
contradict, or leave underdetermined?

Master is not a pure function the bench can call; its layouts are recorded from the real page
(`js/looped-network.js` on the node DOM stub) by `extract.js`, exactly as for the public scenes.

**Scenes.** The generator `dev/lpn-spike/label-bench/generator.js` (committed 2279a57e, ca79cb32)
makes a network as a project document from (family, n, seed), deterministically (mulberry32 over a
hash of the parameters; three separate streams so the same seed gives the same network at every
density and with every ID style). Four families:

- **grid**: a street grid, jittered by 0.2 of the spacing, 8% of links removed (never below two per
  node), trunk mains every fifth street;
- **tree**: rural branched mains from one source, no loops;
- **suburban**: random points at a minimum spacing, a minimum spanning tree, then a looping pass
  (30% of short candidate links, no crossings, no slivers under 25 degrees); 15% of pipes bent;
- **downtown**: 75% of points drawn from a tight Gaussian core, 25% spread wide, joined like
  suburban with 55% looping; so density varies within one view.

Every network has one reservoir (and a 24-inch main from it), one tank per 1000 nodes, a TCV on one
link in 150, terrain-shaped elevations and random demands, and is solved by the vendored EPANET
engine, so the pressure, demand, flow and velocity rows carry realistic text. The label fields are
Novato's (node: ID, P, Qb, Z; pipe: ID, flow, velocity), text 12 px, "Draw link labels along the
link line" on.

**Density** is set by the view, not the network: the first view puts the median nearest-neighbour
distance at `spacingPx` screen pixels, centred on the node nearest the centroid, and the set then
zooms 1.5x, 2x, 3x and 4x about the same node (five views per set). A 5000-node network at 44 px
runs about 20 screens wide: the infinite map.

**Published networks** (`dev/lpn-spike/label-bench/networks/`, licences there): L-Town (BattLeDIM,
782 junctions, CC BY 4.0) and C-Town (BATADAL, 388 junctions, CC BY 4.0), read by the app's own
`.inp` importer. Anytown, the Kentucky set and the other ASCE database networks are CC BY-NC and
are not committed; BWSN, E-Town, Richmond, Net6 and the Exeter set have no licence we could
confirm.

### 1.3 Design

| Exp. | What varies | Sets |
|---|---|---|
| E0 | the public bench (Net1, Net2, Net3, novato-zoom, novato-seq): the reference, "all Net3" | 5 |
| E1 | family (4) x size n (150, 1000, 5000) x density (28, 44, 70 px) x seed (1-6); IDs 'epanet' (2-4 digit numbers) | 216 |
| E2 | ID length: E1's grid and suburban n=1000 at 44 px, the SAME networks, with IDs 'short' (1, 2, 3...), 'long' ('J-10234-A'), 'mixed' (60/25/15) | 36 (+12 from E1) |
| E3 | L-Town and C-Town x density (3) x view centre (seed 1-6) | 36 |
| E4 | master's layout time against network size at a fixed view density (grid, 70 px, n 150-2500) | descriptive |

`matrix.js` in the round folder is this table as code. **Master is not run at n = 5000.** A pilot
(1.6) found its layout time grows with the whole network rather than the view (11 minutes at 2,500
nodes with 515 labels on screen), so its 5000-node scenes are extracted with master's collision pass
switched off (`extract.js` `noMaster`); the scene handed to the placers is byte-identical either way
(checked on the 2,500-node pilot scene).

Each placer runs as the bench runs it (`run.js runBench()`): a fresh instance per set, 3000 ms of
idle before the first view and 250 ms between views, the previous view passed as `prev`. One child
process per (placer, set), a 20-minute limit; a cell that fails or times out is recorded as such
and counts against the placer. Cells run two at a time in a seeded random order on one machine
(Intel i7-7500U, 2 cores / 4 threads, 12 GB, WSL2, node 24), so machine load falls evenly on every
placer; times are comparable between placers, not absolute.

### 1.4 Metrics

Per view, then summed over a set's five views (the set is the unit of analysis):

- **Breaks**: N1 + N3 + N4 + N5 + invalid placements (bench `score.js`). Must be zero.
- **Labels shown %** and **values shown %** (non-ID rows shown / requested).
- **G, missed room** (new, `metrics.js`): of the labels requested, those HIDDEN although free ground
  within 3 text rows could hold their ID row, plus those CUT (fewer rows than requested) although
  free ground within 3 rows could hold the whole label, in that same finished layout. The search is
  the judges' `room.js` exactly (15-degree steps, half-row radii, no symbol, label, Text, pipe; a
  straight leader through no other node and across no other leader); `metrics.js` indexes it on a
  grid and `selftest.js` proves agreement with `room.js` label for label (5,684/5,684 on the public
  scenes under master and on three generated sets under C). This is rule G ("drop ... when all else
  fails") and R1 made measurable: a drop with free ground in reach is a drop before all else failed.
- **Leader on leader per 100 shown labels** (Tom's worst crossing) and **Tom-weighted crossing cost
  per shown label** (his Q05 weights, `judges/weights.js`).
- **Time per layout**: median and maximum over the set's views, ms.
- **Churn rate**: churn / labels compared between consecutive views (bench `stability()`).
- **R11 zoom-in loss rate** (new aggregate): rows lost on zoom-in steps / rows shown at the step
  before; and rows regained.
- **R14 at close zoom**: of the pipe labels still level at 4x, those with room to lie along their
  pipe with the same rows (bench `alignedRoom()`).
- **Leader length** p90 (label heights) and **R7** (pipe labels on their own pipe), reported.

### 1.5 Hypotheses (stated before scoring)

- **H1 (Net3 hides breaks).** At least one placer with zero breaks on E0 has breaks on E1.
- **H2 (the ranking travels).** On E1, C and D show more labels and more values than master, A and
  B, as they do on E0.
- **H3 (time).** Every placer's layout time grows with the number of labels requested; on E1 at
  28 px with n = 5000 at least one placer's median exceeds 1 s. Master's time grows with the whole
  network at a fixed view (E4).
- **H4 (density and shape).** G-missed-room rate rises with density (28 > 44 > 70 px) for every
  placer; by family, downtown is worst and tree best.
- **H5 (churn).** C and D churn more than master on E1, as on the Novato sets.
- **H6 (ID length).** Long IDs lower labels shown % for every placer against short IDs (E2).
- **H7 (the generator is not a toy).** The placers' order on labels shown % and on G-missed-room in
  E3 (published networks) matches their order in E1 (Kendall tau >= 0.6).

### 1.6 Pilot, disclosed

Before this protocol was written, one generated set was run to size the design: suburban, n=1000,
24 px, seed 1 (IDs 'epanet'). On it, A, B, C and D showed 41%, 36%, 56% and 55% of labels; **D had
3 N1 breaks**; median layout times were 0.5, 0.6, 0.4 and 1.9 s. Master's extraction took 140 s
(most of it `shedCrossingSurvivors`), and at 2,500 nodes 655 s. H1 and H3 were therefore written
knowing one instance each; the pilot set is not in the design (24 px is not a design density).

### 1.7 Analysis

For each pair of placers and each outcome, the per-set paired difference over the sets both ran:
**mean difference with a 95% bootstrap interval** (10,000 resamples of sets, seeded) and an **exact
two-sided sign test**, with **Holm's correction** across the ten placer pairs within each outcome.
Master's pairs use the sets master ran (E1 at n <= 1000, E2, E3). Factor effects (family, density,
size, ID style) are reported as per-cell means with bootstrap intervals; H4 and H6 are tested by
paired sign tests on the same networks (density and ID style are paired by construction). H7 by
Kendall's tau between the placers' mean ranks in E1 and E3. A hypothesis is supported when the
test is in the stated direction at Holm-adjusted p < 0.05 for every placer or pair it names.

Rule verdicts (Part 2) follow from the outcomes: a rule is **supported** when the placers that keep
it do better on the outcome it names, **contradicted** when keeping it costs what it claims to
save, and **underdetermined** when the data cannot tell (a rule no placer breaks, or an outcome the
bench cannot see).
