His five examples were tinder, not requirements; no agent of ours is embedded. This note therefore retires the "box" framing of ai-agent-box.md (shapes B and C there are out; shape A is the whole subject). Tags: CITED (source named), OBSERVED (repo path:line), SPECULATION (mine; re-derive).

## 1. The one distinction that decides most of it

An agent answers unanticipated questions only if it has three primitives, not a menu of canned answers:
1. **Read** any part of the model and its results (the whole model, filtered).
2. **Change** a copy of the model (set values, add or resize elements).
3. **Solve** that copy, as often as it likes, and read results again.
With those it can write its own loop: the question is the agent's, the arithmetic is ours. A canned tool such as fire_flow answers only the anticipated question. SPECULATION. (Supporting pattern, CITED: the Technion LLM-EPANET agent generates code against EPANET and retries; its README warns generated code "can interfere with network state", so it recommends a sandbox. https://github.com/yinon-gold/LLMs-in-WDS-Modeling . And the Cambridge Prisms SA Water agent ran base vs future runs by tool calls, with calculation kept on utility systems, doi 10.1017/wat.2025.10012, from journal 2026-10-20.)

## 3. What this says, for Tom's actual question

1. **Yes, an interface for unanticipated questions is possible, and the part that matters is not a protocol.** It is the three primitives (section 1) behind one documented, versioned surface, with edits landing on a scratch copy. Whether that surface is reached by JavaScript, WebMCP or a local MCP server is plumbing around the same surface. SPECULATION, but every row above converges on it.
2. **Shape 3 is the only one a visitor can use today with an agent they already have, without installing anything and without us hosting anything** (Claude in Chrome and Chrome DevTools MCP run page JS; Gemini and Copilot browser agents are screen drivers, shape 2). Shape 4 is the same surface wearing the standard coat; its adoption by agents is the unproven part, so do not wait for it and do not build only for it. CITED facts above, SPECULATION about ordering.
3. **A page-JS agent needs to be told the surface exists.** Nothing today makes a page announce a JS API to an agent; WebMCP is exactly that announcement, and it is not live. So the near-term "how does the agent find it" answer is a sentence the user pastes ("This page has an agent API; call EngCalcs.agent.help()") or a link to a one-page description. SPECULATION. No "llms.txt"-style convention was verified by me; I did not search for one.
4. **Safety is the interface, not an add-on.** Convergent mitigations among shipped products: a visible plan and Apply (QGIS plugin, https://plugins.qgis.org/plugins/ai_agent/), expandable steps (epanet-js, https://epanetjs.com/blog/2026/09/08/epanet-js-august-2026-progress-report/), a browser confirmation for consequential tools (WebMCP annotations), Manual approval mode (Claude in Chrome). For us, SPECULATION: agent edits go to a NEW scenario never the base, show as a diff, and one Undo drops them; scenarios already exist in the app (CLAUDE.md, `lpn_` scenario menu). Read-only by default; a "let my agent edit" switch is the user's click, not the agent's. The same rule as the terrain gate: an agent must not be able to turn on `ec_terrain` or any third-party consent (OBSERVED rule, CLAUDE.md: the four third-party requests, three of them opt-in).
5. **What leaves the machine is the user's agent's business, and we should say so rather than claim the box is private.** Our sentence stays true for us (we receive nothing). It does not cover the user's provider. WaterISAC's policy bars confidential data from AI systems the owner does not control (CITED). A utility with such a policy can still use the interface with a local model, but I did not find a browser agent that drives a page with a local model; the Ollama evidence is a Python proof of concept on EPANET (arXiv 2606.15709, via search summary). So: for policy-bound users the useful shapes are 5 or 1 with a local model, not 2/3/4. SPECULATION.
6. **Does this change the cloud/login question (Task 537, Tom's open Windows-executable and login questions)?** Evidence points the same way as the planning engineer and field operator. Nothing in shapes 1 to 6 needs an account or a cloud save. A Windows executable is not required by any shape; shape 5 is a program, but a cross-platform one. The only shape that would want accounts is 7, and I found no argument for it. CITED/OBSERVED facts above; the conclusion is SPECULATION.

## 4. What I could not find

- **Any agent's actual use of a page API to answer an unanticipated hydraulic question.** The nearest evidence is epanet-js's private-beta agent with a scripting layer (CITED, their August report) and a promoter's LinkedIn post, which is not a test. No measured success rate anywhere.
- **Which agents will actually run page-registered WebMCP tools for ordinary users before 2027.** Sources disagree (Gemini: one article says now, the tracker says early 2027). I weighted the tracker as more specific and dated; both are secondary.
- **What data each browser agent sends to its provider per page.** Claude's permissions page, OpenAI's Atlas help page and Google's auto-browse page do not say. ChatGPT Atlas, per the tracker, was scheduled to stop working 9 Aug 2026 and is replaced by the desktop app; I read that in one secondary source only.
- **Whether a browser page can reach a local Ollama endpoint** from the agent's side: untested.
- **A convention for a page to advertise a JS API to agents** other than WebMCP: not searched.

## 5. If Tom wants a first test (a question, not a roadmap row)

Cheapest experiment that settles the whole matter with evidence: write the three primitives as a documented surface in the page, hand Tom's five examples (and five of Mary's or Perry's own, unannounced) to Claude in Chrome with a one-line instruction, and watch what it does. The harness side already runs headless (dev/lpn-spike). Success measure: does the agent finish a loop of change, solve, read without pressing our buttons, and can Tom see and undo what it changed. SPECULATION on the design; the test is the evidence.
