# An "Ask your AI agent" box in EPANET++ (Mary, 2026-10-21)

Tom's question: could the looped network app have a box where a user asks things we did not build into the interface, and an AI agent with access to the whole project advises or edits? His five examples are judged in section 4. Tags: CITED (named source), OBSERVED (this repo, path:line), SPECULATION (mine; re-derive before relying).

Method note, so the next reader knows what "CITED" is worth here. Autodesk's blog pages returned HTTP 403 to my fetcher, and Bentley Communities pages now redirect to a ServiceNow shell that renders only a title. Where I say "via search summary" below, I read the search engine's quotation of the page, not the page. Bentley's own blog page I did fetch.

## 1. Short answer

- **Several vendors shipped this in 2026, in preview or private beta. The idea is not unusual; it is arriving.** The box that edits the model is the new part: Autodesk (InfoWater Pro 2027.1 onward) and epanet-js (August 2026) both say their agent edits the model.
- **Nobody I found published a benchmark of an LLM doing design optimisation on a water network** (tank drain time, pipe sizing). The only supporting evidence is a pump-scheduling loop and vendor claims. Tom's examples 4 and 5 are in that unproven zone.
- **Nobody found states, in a page I could read, where the model data goes or who the AI provider is** for Bentley's Copilot, Autodesk's Assistant, or the epanet-js agent. That silence is the opening for a product whose sentence is "nothing you draw leaves the browser unless you choose".
- **The in-app box has three possible shapes, with very different privacy cost** (section 6). Only one of them keeps the claim "no accounts" and "we pay nothing".

## 3. How an agent reaches a document in a browser

- **CITED.** **WebMCP**: a page registers tools with `modelContext` (spec `navigator.modelContext`; Chrome's May 2026 docs show `document.modelContext`) with a name, description, input schema and an `execute` function. Annotations include `readOnlyHint`, `untrustedContentHint` and `consequentialHint`, so "agents and the browser" can force a user confirmation before a high-risk tool. Cross-origin iframes are off by default. It is in an **origin trial and still changing** (Chrome docs, https://developer.chrome.google.cn/docs/ai/webmcp/imperative-api ). One October 2026 analysis says no stable release date and broad availability in 2027 at best, with no commitment from Safari or Firefox (via search summary, https://codex.danielvaughan.com/2026/10/15/webmcp-browser-native-model-context-protocol-navigator-modelcontext-agent-web/ ). The spec itself acknowledges prompt injection and exfiltration through tool chaining as unresolved.
- **Why it matters here.** SPECULATION. With WebMCP the page exposes its commands and the user's own browser or extension supplies the agent and the key. We would run no server, take no key, add no third-party request of our own, and the privacy sentence stays true for us. The cost: it works only on browsers and extensions that ship it, and the user's agent may send our model data wherever that agent sends things. We would say so plainly.
- **OBSERVED.** The app's tool surface already exists as commands: Find and replace with a New-value source (dev/lpn-rulings.md:174), scenarios, `EngCalcs.lpnDiagnose`, the solver in the browser, the Curves library (dev/lpn-rulings.md:107-143). The MCP task is dev/ROADMAP.md:363 (Task 818), priority 75.

## 4. Tom's five examples

| # | Example | Kind | Existing command an agent would call | Has anyone shown an LLM doing it well? |
|---|---|---|---|---|
| 1 | Set every element's elevation per the DEM | Deterministic edit | `From Mapbox DEM` as the New-value source in Find and replace (OBSERVED dev/lpn-rulings.md:174) | Not a model task; a tool call. epanet-js, Autodesk and hjlrosales's MCP list this class of edit. hjlrosales has `sample_elevations` (journal 2026-10-20). Caveat below |
| 2 | Set every elevation to 100 | Deterministic edit | Find and replace, a typed number | Trivial; the 90%+ simple-query tier of LLM-EPANET (CITED arXiv 2503.16191) |
| 3 | Advise on the efficiency of my pump curves | Read-only advice | Read the EFFICIENCY curves and pump energy results (OBSERVED dev/lpn-rulings.md:128, dev/pump-energy.md) | Plausible, and the risk is the prose, not the numbers. The agent must quote the number the app computed, not recompute. No benchmark found for pump-efficiency advice |
| 4 | Set a demand multiplier and coordinated pipe sizes to drain the tank(s) in 6 hours | **Design optimisation** | None. A search loop over existing commands: set multiplier, resize pipes, run an extended-period solve, read tank level, repeat | **Not shown.** See below |
| 5 | Set a pump curve, multiplier and pipe sizes for similar velocities and a 50% daily drain-and-fill | **Design optimisation, harder** | None. Needs a cyclic condition (end-of-day level equals start-of-day level) over repeated extended-period solves | **Not shown** |

- **Example 1 caveat. OBSERVED.** The rule is that elevation fill has exactly two doors and "Do not add a third" (CLAUDE.md, `js/lpn-terrain.js` paragraph). An agent calling door two is not a third door. But that door needs the terrain consent gate `ec_terrain`, which is an opt-in third-party request to Mapbox. An agent must not be able to turn that gate on for the user; the user's consent has to stay a user click.
- **Example 4 and 5, the evidence, honestly.**
  - CITED, supports the loop idea. A pump-operation framework asked ChatGPT to propose 24-hour pump settings, ran them in EPANET on Net 3, fed results back and iterated, and its abstract claims more energy-efficient schedules than a genetic-algorithm comparison (MDPI Engineering Proceedings 69(1):3, https://www.mdpi.com/2673-4591/69/1/3/xml , abstract only via search summary; I did not see numbers). Earlier work cited in the Technion paper: Marzouny and Dziedzic 2024, few-shot pump strategies with EPANET feedback.
  - CITED, cuts against it. WaterAdmin (arXiv 2604.10343) states in its abstract that LLMs are "not suitable for directly producing reliable real-time control actions", and puts an optimisation layer under the LLM, which only interprets context. Abstract only.
  - CITED, accuracy trend. LLM-EPANET: 56-81% overall, over 90% on simple queries, falling as queries get complex (arXiv 2503.16191).
  - CITED, vendor claims, no data. epanet-js lists "designing a pump for a given duty" and "sizing a tank" as agent tasks (August 2026 report). No measured success rate published.
  - NOT FOUND: any paper measuring an LLM against a known optimum on pipe sizing, or on "drain the tank in N hours". I searched for LLM against GA on Hanoi and New York Tunnels; the only hit was a multi-agent reduced-order-model paper (arXiv 2607.10994) whose water results I could not read.
  - OBSERVED, nearby tool. hjlrosales's MCP has `optimize_network` as "a grid of candidate edits on copies" and `run_candidate` (journal 2026-10-20), i.e. the search is done by the tool, not the model.
- **SPECULATION.** The shape that has evidence behind it is that the model frames the problem, states the constraints back (which demands, minimum pressure, maximum velocity, which pipes may change), and a deterministic search does the iterating. Example 4's multiplier alone is a one-variable monotone search; the pipe sizing is the open part and is underspecified as Tom wrote it ("coordinated", "similar velocities"). An agent that answers it without asking what pressure floor and which pipes is guessing. Example 5 should not be a first demo.

## 5. Failure stories

- **CITED.** In-domain accuracy falls with complexity (above). KWR's June 2026 workshop stressed human oversight, prompt injection and hallucination (https://www.kwrwater.nl/en/actueel/from-chatbots-to-agents-ais-next-wave-in-water/ , journal 2026-10-20).
- **CITED.** The Technion framework's README warns that generated code run directly on the host "can interfere with network state" and recommends its sandbox, on by default; failed code is retried (default 5). https://github.com/yinon-gold/LLMs-in-WDS-Modeling
- **CITED, secondary trackers, no postmortem read.** A Cursor agent reportedly deleted a company's production database and backups in about nine seconds (PocketOS, April 2026, logged by the OECD AI Incidents Monitor, https://oecd.ai/en/incidents/2026-04-27-6153 ); Replit's July 2025 deletion during a code freeze (Adversa compilation, https://adversa.ai/blog/ai-coding-agent-incidents/ ). Tool poisoning through MCP descriptions is described as research, "I didn't find a confirmed in-the-wild case".
- **Mitigations the shipped products use, to copy or not.** QGIS plugin: a visible plan and an Apply button. epanet-js: steps you can expand to see the exact edits. WebMCP: `consequentialHint` forces a confirmation. SPECULATION: for a model editor, the strongest one is a preview of the change as a diff and one Undo for the whole agent action.
- **NOT FOUND.** A published failure of Bentley's Copilot or Autodesk's Assistant in hydraulics. Both are in preview and too new.

## 6. Three shapes of the box against our constraints

| Shape | Who is the agent / who pays | Privacy and storage cost | Accounts |
|---|---|---|---|
| A. The user's own agent calls us (local MCP, Task 818, or WebMCP) | The user's agent and subscription | Nothing new in our code. Local MCP keeps the "nothing reaches our server" sentence. WebMCP adds no request of ours | None |
| B. A box in the app, user pastes their own key, the browser calls the provider directly | The user pays the provider | **A fifth third-party request**: a new paragraph in `privacy.php` (CLAUDE.md: "A fifth service is a new paragraph in `privacy.php`"), opt-in and named, and a key kept on the device, which is new storage under `dev/storage-rulings.md` (exemption test, or analytics-consent gate, and deletion on withdrawal). The prompt and whatever of the project the agent reads go to the provider | None |
| C. The vendor (us) supplies the AI | We pay per use | Prompts and models pass through our server: ends "nothing a user draws is uploaded". Needs accounts or rate limiting | Yes |

- **SPECULATION.** C contradicts the project's premises and its constraint of no database or accounts; I found no evidence that argues for it. epanet-js's agent is on paid plans, which is C's cost structure, and is Iterating's business, not ours. This extends the 537 pile only mildly: Task 537 (dev/ROADMAP.md:1152) is about a phone reaching a PC's model, not an AI box, so it is not direct evidence either way. On "logins and cloud saves", my evidence points the same way as the planning engineer and field operator: an AI box does not need an account unless the vendor pays for the model.
- **CITED.** Utility policies bar confidential data from AI systems the owner does not control (Arlington TX, Central Tablelands Water draft, WaterISAC; journal 2026-10-20). SA Water's case kept all calculation inside its own systems (Cambridge Prisms: Water, doi 10.1017/wat.2025.10012). So shape B sends a utility's network to a provider its policy may forbid; the local-model route (Ollama, as the Jordan study) is the one that fits such a utility, and from a browser page it would call a localhost endpoint. SPECULATION: whether a browser page can call a local Ollama endpoint depends on the user's CORS setting; untested.
- **Which is the "big idea"?** SPECULATION. The box with the evidence behind it is A via WebMCP or local MCP, with every tool a command the app already has and every answer ending in a view the engineer can check on screen. It is the only shape where we do not decide what AI provider or what data policy a utility must accept. The thing that is the product, whatever shape, is the exposed command set and the diff-and-undo, not the chat window. Tom's five examples would all be answered by the same ten or so tools.

## 8. WaterGEMS CONNECT: annotation shows IDs, not Labels

**Short version. I could not find a Bentley page that says why a "Label" annotation would show an ID, and I could not reproduce it (no software). What follows is what the documentation does support, and a ranked list of causes that is mine.**

- **CITED.** The two fields are different. Bentley's Pipe Attributes page: ID is the "Unique identifier assigned to this element"; Label is a "Descriptive label for this element" (https://docs.bentley.com/LiveContent/web/Bentley%20WaterGEMS%20SS6-v1/en/GUID-7E022352A26641E7860CC5BFCDBA312B.html , fetched). A Bentley community article, quoted in a search summary: WaterGEMS CONNECT "internally keeps track of elements using a read-only ID property" and "users can and should identify elements using labels"; labels are "purely for display". (Original page now redirects to a ServiceNow shell; I did not read it.)
- **CITED.** The annotation dialog: "Field Name: Specify the attribute that is displayed by the annotation definition", with Prefix, Suffix and a Free Form option (https://docs.bentley.com/LiveContent/web/Bentley%20WaterGEMS%20SS6-v1/en/35070.html , fetched). The page does not mention Label versus ID.
- **CITED.** Default labels come from Tools > Options > Labeling (prefix, next number, increment, digits, suffix per element type); Relabel in a FlexTable renames placed elements (https://docs.bentley.com/LiveContent/web/Bentley%20WaterGEMS%20SS6-v1/en/GUID-EC27E25F4B204227893CE1CFE4178317.html , fetched).
- **CITED, via search summary.** Open Element Symbology with View > Element Symbology (Ctrl+1), pick the element type, New, annotation; "Selection Set": <All Elements> or a set; folders turn groups on and off. Selection-set annotations need the Refresh Element Symbology button after a scenario or input change (V8i-era wiki article 23478). Free Form annotation: pick the Free Form entry in Field Name and use the ellipsis to build a line that combines fields.
- **CITED, via search summary.** If ModelBuilder is keyed on GIS-ID, the start and stop node names go into the GIS-ID field, not Label; "there is not a mechanism in place to tell the program to also use the GIS-ID as the label" (Bentley wiki 43108). If the model came in through ModelBuilder or a GIS key, the thing that looks like an ID may be the GIS-ID.

**Steps to try, in this order (SPECULATION as a diagnosis; each step is documented behaviour).**
1. Open a Junction FlexTable (View > FlexTables) and look at the columns Label and ID side by side (use the column chooser if one is hidden). If Label already shows J-1, the data is right and the annotation is bound to the wrong field. If Label shows the same number as ID, the labels were never set to J-1: use Tools > Options > Labeling to set Prefix J-, then Relabel in the FlexTable (or import them).
2. In Element Symbology, double-click the annotation (or New > Annotation) and open the Field Name list. Choose the entry whose name is exactly Label, not ID, not GIS-ID, and not a free-form line you did not mean. Check the list for both a Label and an ID-looking entry before you assume the one you picked was Label.
3. If the list only offers something that behaves as ID, use the Free Form entry: Field Name > Free Form > ellipsis, and insert the Label field.
4. Set Selection Set to <All Elements>, then press Refresh Element Symbology and redraw.
5. If it still shows an ID, send me a screenshot of the Annotation Properties dialog open on the Field Name list. That one picture decides it; I will not guess further.
