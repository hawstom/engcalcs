# First-time view of the map app (Ida, 2026-10-24)

What I saw (OBSERVED, Chromium 1400x900, fresh profile): the first view has NO boxes at all. The menu bar, the toolbar, one tab ("Project1") and a gallery of example cards, with a one-line "Mode: Select..." strip sitting on top of the gallery's welcome heading and clipping it. After opening Net3 the map is clean but a yellow "Opened ... as a copy" notice sits over the Mode line. The consent banner takes about 150 px of the bottom. A first-timer today sees an app with no boxes, so they cannot learn that boxes exist, let alone that they hide.

RANKED RECOMMENDATIONS

1. First view: yes to your layout, with one change. Open the six boxes you named, but open them DOCKED AND PINNED (visible, not hidden) except two. Leave Scenario Manager (left) and User Manual (right) auto-hidden. Why: (a) a mix shows both ways of doing business, which answers "not the only way" without a word of explanation; (b) auto-hide demonstrated on two boxes reads as a feature; on all six it reads as a screen with nothing on it, because an auto-hidden box is only an edge tab. Silence-vs-noise: six pinned boxes is noise, six hidden is silence, four open and two edge tabs is a quiet room with two visible doors. Settings and Properties pinned on the right (Properties first, since it is what clicking an asset fills), Libraries as a tab beside them, Junctions pinned left. Phone: none of this opens (docking is not offered there), the map stays.
   Cost: first-visit defaults only; a returning visitor's saved layout wins. Roughly one afternoon, no new words, no translation.

2. Do not open them on top of the example gallery. The boxes eat about 40 percent of the width at 1400, and the gallery is the way into a drawing. Open the boxes when the first project opens (an example or Start here), not before. That is also when Properties and Junctions have something to show.

3. Settings table, (d) the reasoning, as I find it: Settings is the home of everything that is true of the WHOLE project (units, friction method, defaults, prefixes, colouring, labels). Properties is what is true of ONE selected asset. Your membership rule, in the scope doc: "if it is for the entire project, it is in Settings." The second reason is the one you borrowed from Autodesk: each setting says where it is kept (project, this browser). Without a single home, whole-project choices scatter across menus and a reader cannot find or audit them. Distill it as one sentence under the Settings title bar, quiet type: "Settings apply to the whole project. Properties apply to what you selected." One string by 27 languages; it is the cheapest teaching you can buy, and it also names the pairing that justifies putting them side by side in item 1.

4. Examples (e). Judging your four: the two hydrants are the right kind, a question a consulting engineer is actually asked. "Home or farm well and pressure tank (40 L [10 gal] drawdown)" is good because it is small and ends in a number someone checks. "Community well and elevated tank, daily analysis" is good and is also the only one that shows the time controls. Concerns: "from everywhere" is vague; try "fed from both sides". Titles state a task, not a file, which is the right turn from "EPANET Net3". What is missing: (1) an example that is nearly empty, a reservoir, a pipe, a junction, so a person can add the second pipe; (2) a pump curve and a pump (Elm Street is close); (3) one with scenarios already made, since Net1-Scenarios exists. Keep the six EPANET ones, but move them under a second heading, "EPANET's own examples", so the first row is yours. This matches your Task 823 and I have read no more than its roadmap line.

5. Is example opening logged (e)? Partly. OBSERVED (js/looped-network.js:40773, lib/config.inc.php:461): a visitor's FIRST action is logged as the word "example" (versus element, backdrop, import), once per page load. WHICH example is not logged. The file name is stored in the project (project.gallery) but nothing sends it. Counting which one is a new log detail on the existing lpn signal, an analytics-gated change with no new storage, but the consent text and the log-doc comment must say so. If you want to rank examples by use, that is the cheapest way; I would add it before reordering the gallery.

6. Workspace examples named after agents (f): good idea, wrong names. A workspace is a layout plus a theme plus an example. Named after people they tell a stranger nothing about what they get, and "Ida's workspace" means nothing to someone who has never met Ida. Name them for the job: "Review workspace" (Properties and Tables), "Design workspace" (Libraries, Junctions), "Field workspace" (big targets, few boxes). You can put the agent's first name in the description line ("arranged the way our field operator works"), which is a story and not a label. It also needs a mechanism: a saved layout is browser-only today and never rides in a project file, so a workspace example is a new kind of object, which is a separate task. My first-visit default in item 1 is the cheaper half of it.

7. Clean map (g). Hide the messenger (the yellow "Opened as a copy" notice): it already does. Keep the Mode line: your own 2026-09-22 ruling removed it from Clean map, and I agree, it is the only statement of what a click will do. The real defect in the screenshot is the Mode line overlapping the gallery welcome heading, which is a layout bug to fix first (give the strip its own row).

IF ONLY ONE: item 1, with item 2's timing.
