# Where each setting is kept

ROADMAP Task 739. Tom, 2026-09-28, on learning that dragged column widths live in the browser:
*"Systematically disclose to users where things are stored. Autodesk does this so well that I, a
user, can cite by memory that variables are stored in the drawing (project), session, or user
profile. Every sysvar listing includes 'Where it's stored.'"*

## The three classes, and the one key each

| Class | Words on screen | Key | Meaning |
|---|---|---|---|
| Project | Saved with the project | `lpn_saved_project` | Rides in `serializeProject()`; goes to the file and to a colleague |
| This browser | Saved in this browser | `lpn_saved_browser` | A `localStorage` key; follows the device, never the file |
| This session | Not saved | `lpn_saved_session` | Forgotten on reload. No Settings control is in this class today; the key exists so the next one is not an excuse to invent a fourth |

CLAUDE.md's rule is unchanged: a `lpn_` setting belongs to the project **or** the browser, never
both. The harness reports a control that changed both as `both` and fails it.

## How it is disclosed

- **A Settings sub-heading** carries one quiet marker after its title (`.lpn-saved`), inside the box
  body and never in the title bar. The class is declared in Looped-Network.php as
  `data-saved="..."` and the marker is written by `lpnSavedMark()`.
- **A row whose home differs from its sub-heading's** carries its own marker under its name
  (`row(..., saved)` in js/looped-network.js). Today: *Show the run progress box* under Hydraulics
  (this browser, under a project heading).
- **Column width** is not a Settings control. Its discovery paths are the Width entry in Manage
  columns and a 1 s tip on the column divider, both saying the width is kept in this browser. The
  divider tip is never put on a device that cannot hover.
- The index and the search read the heading's own words: `setboxHeadingText()` leaves the marker
  out of the index, and the search matches the marker's words (search "browser").

## What is kept in this browser, and by which control

Derived from `EC_LPN_FURNITURE` in `dev/scripts/lpn_furniture_check.php`; the check
`setting_scope_check.php` fails if a key there is not named here.

| Key | Control |
|---|---|
| `lpn_pane` | Height and open tab of the bottom pane (drag the pane edge, pick a tab) |
| `lpn_rpane` | Width of the right pane (drag its edge) |
| `lpn_setbox`, `lpn_findbox`, `lpn_libbox`, `lpn_ffbox`, `lpn_energybox`, `lpn_cmpbox`, `lpn_reportbox`, `lpn_statusbox`, `lpn_fullbox`, `lpn_notesbox`, `lpn_hotkeysbox`, `lpn_contourbox` | Position, size and openness of each standing box (drag, resize, close) |
| `lpn_panecols` | Column width, order and hidden columns of the Tables (drag a divider or heading, Manage columns) |
| `lpn_runbox` | Settings > Calculation > Hydraulics > Show the run progress box |
| `lpn_scnbasic` | Scenarios > Basic mode |
| `lpn_areahint` | Settings > Map and page > Page > Show the selection help, and the bubble's own checkbox |
| `lpn_survey_format` | The column order last chosen when importing a surveyed point list |
| `lpn_show_titles` | None: the control is gone (Task 625) |

Not settings, and not in the inventory above: `lpn_project_*`, `lpn_index` and `lpn_identity` are the
project store and the lock identity, written through `writeJSON()`; the consent and language
cookies are in `dev/cookie-storage-inventory.md`.

the Tables' sort order, filter and heading selection, and the Settings search text. None is a
Settings control, so none carries a marker. This list is read from code, not driven; the harness
drives only the Settings box.

## Settings box inventory (generated)

a changed `lpn_project_*` record is Project, a changed other `lpn_*` key is This browser, a change
that reached neither is This session, both is a defect. One control per row is driven (a row of ten
checkboxes is one setting written by one handler). Run on Net3 with the box in its default state, so
rows that exist only on demand (a custom property, a colour-range editor, the EPANET-only accuracy
rows) are counted only when present. Regenerate with
`node dev/lpn-spike/setting-scope-browser-harness.js --write`.
